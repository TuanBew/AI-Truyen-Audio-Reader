## 1. Goals and constraints

AudioTruyen v2 is a **private, single-user** web app for reading and listening to Vietnamese web novels at the same time ("read-along"), with **multi-voice, emotion-aware narration** generated by a **self-hosted TTS model**.

### Decisions locked during brainstorming

| Topic | Decision |
|---|---|
| Audience | One user (the owner). Private app, sign-up disabled. Not a public distribution service. |
| Primary usage | Desktop, reading while listening. Sentence/segment highlight is the core experience. PWA/offline is a non-goal. |
| Voice | Multi-voice: narrator + per-character dialogue voices (male/female defaults, per-character overrides). Default Southern presets: narrator "Đức Trí", male "Thái Sơn", female "Mỹ Duyên". |
| Speaker attribution | Three pluggable strategies, chained: cloud LLM (Gemini free tier) → local LLM (llama.cpp, CPU) → heuristic. |
| Emotion | Layered: LLM labels emotion per segment → VieNeu clones from a per-emotion reference clip only for the (voice, emotion) pairs enabled after spike S1 (narrator/angry, male/angry, male/whisper; female/happy and female/sad **provisional** until the M4 re-test). Every other segment, including `neutral`, is spoken by the preset voice itself (`voice=` preset id, no clone; the VoxCPM2 neutral clip is not used) → prosody post-processing. Non-verbal tags dropped (S1). |
| TTS engine | VieNeu-TTS v3 Turbo (Apache-2.0), local, CUDA by default (verified in S3); ONNX CPU fallback must be verified in M2. |
| Audio storage | Cloudflare R2. Fallback when worker is offline: Microsoft Edge TTS, single voice, not persisted. |
| Sources | `SourceAdapter` interface; v2 ships the truyenfull adapter only. |
| Architecture | Approach A: Supabase as hub, worker makes **outbound connections only**. |
| Reader layout | Layout A: focused reading column, drawers for TOC and cast, docked player bar. |
| Theming | Fully user-customizable colors (6 seed colors, derived tokens), presets, reading typography controls. |
| Extra features | Pronunciation lexicon, sleep timer + speed, follow novels for new chapters, bookmarks + notes + listening stats. |
| Hosting | Vercel (web), Supabase free (DB/auth/realtime), R2 free (audio), owner's Windows laptop (worker). |

### Hardware constraint

Worker host: Windows 11 laptop, NVIDIA GTX 1650 Max-Q **4 GB VRAM**. Only one model may hold VRAM at a time. The local LLM runs on CPU. VieNeu v3 Turbo measured 1369.9 MiB (≈1.34 GiB) torch peak VRAM on the GTX 1650 (spike S3; allocator peak, excludes CUDA context). Its ONNX CPU path (published as ~2x realtime) did not load in S3, so running without a GPU stays unverified until M2 re-benchmarks it.

### Non-goals (v2)

- Public multi-user service, sign-up, sharing.
- Mobile-first UI, PWA install, offline downloads, Web Push.
- Word-accurate forced alignment (word highlight is interpolated).
- EPUB/TXT import (the adapter interface leaves room for it later).
- Real-time conversational voice agents. Dograh and Pipecat were evaluated: they orchestrate STT→LLM→TTS for live calls and do not provide Vietnamese narration, so they are not used.

## 2. Research findings that shaped the design

### 2.1 Truyenfull "locked chapters"

Verified on 2026-10-13 against `truyenfull.live`:

- The server returns the **full chapter text** inside `#chapter-c` for every chapter (tested chapters 1, 2, 349, 350; ~6,200-6,600 chars each).
- The lock is purely client-side: `static.truyenfull.live/js/minify.js` hides `#chapter-c` and shows `#ads_click_view_chapter` when the cookie `truyenfull_cf_ad_content` is absent and `chapter_num >= 2`. Clicking the ad sets the cookie for 10 minutes.
- A server-side HTML parser therefore never encounters the lock. No interaction or circumvention logic is needed.
- The chapter body ends with SEO junk (`truyen full, truyenfull, truyenfullvn, truyenfulllive ...`) that must be stripped.
- Text contains obfuscated words such as `c.h.ử.i` that must be normalized.
- Novel pages expose `<input id="truyen-id" value="...">`; chapter URLs follow `/{slug}/chuong-{n}/`.
- The page embeds Cloudflare Turnstile. Residential IP requests return 200; datacenter IPs (Vercel) may be challenged. **All scraping runs in the worker.**

Personal-use note: reading the HTML skips the site's ad monetization. This is acceptable only because the app is private and single-user.

### 2.2 TTS model selection

|---|---|---|---|---|---|

Verified on GTX 1650 (S3): sequential RTF 0.22, batch RTF 0.13, first sentence 0.52 s, 1369.9 MiB (≈1.34 GiB) torch peak VRAM (presets only; clone RTF re-measured in M2). ONNX CPU (published ~2x realtime) not verified. | Experimental non-verbal tags exist but are not used (S1: one broken, one inaudible); style follows the reference clip for the enabled pairs (5.10) | **Chosen** |

### 2.3 Gemini free tier

- Limits are per **project**, not per key; RPD resets at midnight **Pacific time**.
- Free-tier quotas are low and volatile (Flash cut to ~20 RPD in Dec 2025; Flash-Lite reported ~15 RPM / 500 RPD on 2026-10-13). 429s can occur below the displayed quota.
- Model IDs change over time. The worker must discover available models at startup, never hardcode a single ID.

## 4. Data model (Supabase Postgres)

Every user-data table (all tables below except `worker_status` and `llm_usage`) has `user_id uuid not null references auth.users on delete cascade`, RLS enabled, anon denied. Policies: `authenticated` has full access to its own rows in `novels`, `chapters`, `characters`, `voices`, `lexicon`, `jobs`, `progress`, `listened_chapters`, `bookmarks`, `listen_sessions`, `settings`; read-only access to its own rows in `chapter_analysis` and `chapter_audio` (written only by the worker); read-only access to all rows of `worker_status` and `llm_usage`. The worker uses the service-role key and bypasses RLS; when it inserts child rows it copies `user_id` from the parent novel.

```sql
novels (
  id uuid pk, user_id, source text,            -- 'truyenfull'
  source_novel_id text, url text, slug text,
  title text, author text, cover_url text, description text,
  status text,                                 -- 'ongoing' | 'completed' | null
  chapter_count int, followed bool default false,
  auto_synthesize_new bool default true,
  last_checked_at timestamptz, created_at, updated_at,
  unique (user_id, source, source_novel_id)
)

chapters (
  id uuid pk, novel_id fk, index int, title text, url text,
  text text null, text_hash text null, fetched_at timestamptz null,
  is_new bool default false,                   -- set by scheduler, cleared on open
  unique (novel_id, index)
)

characters (
  id uuid pk, novel_id fk, name text, aliases text[],
  gender text check in ('male','female','unknown'),
  voice_id uuid null fk voices, color text null,  -- null = auto from theme
  manual bool default false,                   -- true = never overwritten by analysis
  unique (novel_id, name)
)

voices (
  id uuid pk, name text, kind text check in ('preset','clone'),
  preset_name text null,                       -- VieNeu preset id; neutral playback (and every non-enabled
                                               -- emotion) = infer(voice=preset_name), no clone
  refs jsonb,                                  -- { "<emotion>": { "key": "voices/{id}/{emotion}.wav",
                                               --   "enabled": bool, "provisional": bool } }
                                               -- keys: emotions of 4.1 except "neutral" for kind='preset';
                                               -- kind='clone' voices also need "neutral" (no preset to fall
                                               -- back to). A ref is used only when "enabled" is true (5.10).
  gender text, is_default_narrator bool, is_default_male bool, is_default_female bool
)

lexicon (
  id uuid pk, novel_id uuid null,              -- null = global
  pattern text, replacement text, is_regex bool, enabled bool,
  position int                                 -- application order
)

chapter_analysis (
  chapter_id fk, text_hash text, strategy text, strategy_version int,
  segments jsonb, created_at,
  primary key (chapter_id, text_hash, strategy, strategy_version)
)

chapter_audio (
  id uuid pk, chapter_id fk, voice_hash text,
  status text check in ('queued','partial','ready','failed'),
  provider text,                               -- 'vieneu'
  attempt int not null default 1,              -- synthesis run number; a re-run increments it and resets
                                               -- init_key/chunks/full_key/duration_ms (4.3, 5.1)
  init_key text null,                          -- shared WebM init segment (init.webm)
  chunks jsonb,                                -- [{ key, start_ms, end_ms }]: cluster media segments of one
                                               -- continuous encode, times read from the muxed stream (5.6)
  full_key text null, duration_ms int null,
  segments jsonb,                              -- see 4.1
  warnings jsonb, created_at, updated_at,
  unique (chapter_id, voice_hash)
)

jobs (
  id uuid pk, user_id,                         -- owner, so the web app can enqueue and read jobs through RLS
  type text check in ('search','fetch_novel','fetch_chapter','synthesize','check_updates'),
  payload jsonb, priority int,                 -- 0 interactive, 10 prefetch, 20 background
  status text check in ('queued','running','done','failed','cancelled'),
  attempts int default 0, max_attempts int default 3,
  run_after timestamptz default now(),
  lease_until timestamptz null, worker_id text null,
  result jsonb null, error text null, created_at, updated_at
)

worker_status (worker_id text pk, last_seen timestamptz, version text,
               device text, queue_depth int, current_job uuid null)

llm_usage (model text, day_pt date, requests int, tokens int,
           locked_until timestamptz null, primary key (model, day_pt))

progress (novel_id pk-part, user_id pk-part, chapter_id, segment_index int,
          position_ms int, updated_at)
listened_chapters (chapter_id, user_id, finished_at)
bookmarks (id, chapter_id, segment_index, quote text, note text, created_at)
listen_sessions (id, chapter_id, started_at, seconds int)
settings (user_id pk, data jsonb, updated_at)  -- see 7.1 / 6.4
```

`claim_job(worker_id text, lease_seconds int)` is a SQL function: selects the first `queued` job with `run_after <= now()` ordered by `priority, created_at`, `FOR UPDATE SKIP LOCKED`, sets `running`, `lease_until`, `worker_id`, increments `attempts`, returns it. A companion `requeue_expired_jobs()` resets `running` jobs whose `lease_until < now()`. `begin_chapter_audio(chapter_id uuid, voice_hash text)` creates or re-attempts a `chapter_audio` row and returns `(id, attempt, status)` (5.1). Only the service role may execute these three functions.

### 4.1 Segment schema

```json
{
  "i": 12,
  "kind": "narration" | "dialogue",
  "src": [1043, 1121],          // char range in ORIGINAL chapter text (for highlight)
  "speaker": "Lâm Phong" | null,
  "gender": "male" | "female" | "unknown",
  "emotion": "neutral" | "happy" | "sad" | "angry" | "fearful" | "whisper" | "shout" | "tender",
  "intensity": 0.0-1.0,
  "voice_id": "uuid",
  "start_ms": 81234, "end_ms": 85610
}
```

### 4.2 voice_hash

`sha256(narrator_voice_id, default_male_id, default_female_id, sorted(character→voice overrides for this novel), lexicon_version, pipeline_version)[:16]`. Changing voices or the lexicon produces a new hash; old audio is kept until garbage-collected. GC deletes R2 objects (a) whose `chapter_audio` row is older than 30 days and not the current hash, and (b) under an `{attempt}` prefix other than the row's current `attempt` (abandoned attempts, 4.3) once that attempt is superseded.

### 4.3 R2 key layout

```
audio/{novel_id}/{chapter_id}/{voice_hash}/{attempt}/init.webm
audio/{novel_id}/{chapter_id}/{voice_hash}/{attempt}/seg-{0000}.webm
audio/{novel_id}/{chapter_id}/{voice_hash}/{attempt}/full.webm
voices/{voice_id}/{emotion}.wav
```

`init.webm` is the shared init segment and `seg-{0000}.webm` are the cluster media segments of one continuous encode per chapter (spike S2). `{attempt}` is `chapter_audio.attempt`: a re-run never overwrites objects of an earlier attempt (VieNeu has no seed, so a re-run produces different audio and different cluster cuts), and the player only reads keys of the row's current attempt.

`full.webm` is **not** the raw concatenation: live (`-live 1`) output has no Duration and no Cues, so it is not seekable. On completion the worker writes `init.webm` + all `seg-*` in order to a temporary `concat.webm` and remuxes it to a file (not a pipe, so the muxer can write Duration and Cues): `ffmpeg -i concat.webm -c copy full.webm`, then uploads `full.webm`.

## 5. Worker

### 5.1 Job loop

- On start: register in `worker_status`, discover Gemini models, load VieNeu lazily on first `synthesize`.
- Wake sources: Supabase Realtime subscription on `jobs` inserts + 30 s polling fallback.
- Heartbeat every 15 s: updates `worker_status`, extends `lease_until` of the current job, calls `requeue_expired_jobs()`.
- One job at a time. Lease 5 min, extended by heartbeat.
- Failure: `attempts < max_attempts` → `queued` with `run_after = now() + 2^attempts min`; else `failed` with a human-readable `error`.
- `synthesize` jobs whose `voice_hash` no longer matches the current settings are marked `cancelled` without work.
- Row ownership: only the worker creates `chapter_audio` rows. The web app enqueues `synthesize` jobs and reads rows; it never inserts them. When a `synthesize` job starts, the worker calls `begin_chapter_audio(chapter_id, voice_hash)` (SQL function): it inserts the row with `attempt = 1, status = 'queued'` if absent; if a non-`ready` row exists it increments `attempt` and resets `init_key`, `chunks`, `full_key`, `duration_ms` to null/empty and `status` to `'queued'`; if the row is `ready` it returns it unchanged and the job ends as done. The function returns `(id, attempt, status)`.
- `synthesize` re-runs (lease expiry after a crash, retry after failure) therefore always start a new attempt and write all new objects under the new `{attempt}` prefix (4.3). They never resume or overwrite a previous attempt. Objects of abandoned attempts are removed by GC (4.2).
- Attempt fencing: every worker write to `chapter_audio` after `begin_chapter_audio` is conditional on the attempt it owns (`... WHERE id = $id AND attempt = $attempt`). If an update affects zero rows, a newer attempt has superseded this run (e.g. the laptop slept past its lease): the worker stops the job immediately, uploads nothing more, and marks its job `cancelled`.

### 5.2 SourceAdapter

```python
class SourceAdapter(Protocol):
    id: str                                   # 'truyenfull'
    def matches(self, url: str) -> bool: ...
    def search(self, query: str) -> list[NovelSummary]: ...
    def novel(self, url: str) -> NovelDetail: ...          # metadata + full TOC
    def chapter(self, url: str) -> ChapterContent: ...
```

Truyenfull adapter:
- `httpx` with a desktop browser User-Agent, ~1 req/s with 0.3-0.8 s jitter, retries with backoff on 5xx/timeouts.
- TOC: paginate the novel's chapter list until exhausted; implementation must inspect the live pagination (page links or AJAX) and record fixtures.
- Chapter: parse `#chapter-c`, drop descendant elements whose `id` or any class **starts with** `ads` (prefix match, e.g. `#ads-chapter-top`; never a substring match, which would also hit words like `roads`), convert `<br>` to line breaks, strip the trailing SEO keyword block with a pattern **anchored to the end of the text** (a match in the middle of the chapter is never removed). Carried to M2 from the M0 review.
- Validation: raise `ParserBroken` if text is empty or under 500 chars for a chapter whose title is present; raise `SourceBlocked` on Cloudflare challenge markers or HTTP 403/503 with challenge body.

### 5.3 Text pipeline

1. **Normalize** (TTS input only; display text stays original): Unicode NFC; de-obfuscate dotted words (`c.h.ử.i` → `chửi`, regex for single Vietnamese letters separated by dots); numbers, dates, units, abbreviations via VietNormalizer; then lexicon rules (global by `position`, then novel-level). Each transformation keeps an offset map back to original text.
2. **Segment**: split paragraphs; within paragraphs separate dialogue (`"..."`, `“...”`, lines starting with `-`/`–`) from narration; split segments over ~250 chars at sentence boundaries. Each segment records its `src` range in original text.
3. **Analyze** (speaker, gender, emotion, intensity) via strategy chain (5.4). Cached in `chapter_analysis`.
4. **Resolve voice**: narration → narrator voice; dialogue → character's voice, else default by gender, else default narrator-alt. Then, if the voice has an **enabled** ref for the segment's emotion (5.10), clone from that clip (`infer(ref_audio=...)`); otherwise, including every `neutral` segment, speak with the preset voice itself (`infer(voice=preset_name)`, no clone). Only `kind='clone'` voices use a `neutral` ref clip.

### 5.4 Speaker/emotion strategies

```python
class SpeakerStrategy(Protocol):
    name: str; version: int
    def analyze(self, segments: list[Segment], roster: list[Character]) -> list[SegmentLabel]: ...
```

Chain order configurable in settings (default: `gemini → local_llm → heuristic`). A strategy result is accepted only if it passes JSON-schema validation and covers every segment id; otherwise the next strategy runs.

- **gemini**: one request per chapter. Input: numbered segments + compact roster. Output: compact JSON array `[[i, speaker, gender, emotion, intensity]]` plus `new_characters`. No non-verbal tags (dropped after spike S1). Uses structured output (response schema) where the model supports it.
- **local_llm**: llama.cpp (via `llama-cpp-python`) on CPU, Qwen-class 1.5-3B instruct GGUF Q4, same prompt and schema, processed in windows of ~40 segments. Model file path in `.env`; strategy is skipped if absent.
- **heuristic**: dialogue speaker from adjacent attribution verbs (`nói`, `hỏi`, `quát`, `gầm lên`, `thì thầm`, ...) and the nearest name or pronoun (`anh/hắn/ông` → male, `cô/nàng/bà` → female); emotion from verb lexicon and punctuation (`!` → intensity up, `...` → sad/tender, `?` neutral). Unknown → `unknown` gender, `neutral`.

Roster merge: new characters inserted; existing non-`manual` rows may update `gender` only when the new label has higher confidence; `manual` rows are never changed.

### 5.5 Gemini client and rate limiting

- Models from `GEMINI_MODELS` env (ordered, default: newest Flash-Lite, then newest Flash), filtered at startup by `models.list`.
- Limits per model from `GEMINI_LIMITS` env (`rpm`, `rpd`), applied at **80%** of the configured values.
- `llm_usage` row per `(model, day_pt)` persists counts across restarts. Minimum spacing between requests = `60 / effective_rpm` seconds.
- 429 handling: if the error's quota metric is per-minute, sleep for `RetryInfo.retryDelay` (default 60 s) and retry once; if per-day, set `locked_until` to next midnight Pacific and move to the next model. All models locked → next strategy.
- Budget priority: jobs with priority 0-10 may use Gemini freely; priority 20 (background/new chapters) only when today's remaining budget is above 50%.
- API key lives only in `worker/.env` (`GEMINI_API_KEY`), never committed, never sent to the web app.

### 5.6 TTS and audio

```python
class TTSProvider(Protocol):
    name: str
    def synthesize(self, text: str, voice: VoiceRef, emotion: str,
                   intensity: float) -> np.ndarray: ...   # float32 mono @ provider rate
```

- `vieneu` provider: VieNeu v3 Turbo; default device `cuda` (spike S3 on the GTX 1650: sequential RTF 0.22, batch RTF 0.13, first sentence 0.52 s). The ONNX CPU fallback is used only when CUDA is unavailable and is unverified: S3 could not load the ONNX model (huggingface_hub 2.x symlinked cache fails onnxruntime's external-data path check). M2 must load the ONNX model from a real `local_dir` (or pin `huggingface_hub<1.0`) and re-benchmark CPU RTF before relying on it. Speaks with `voice=preset_name` by default and clones from an emotion ref only for enabled pairs (5.3 step 4, 5.10). S3 measured presets only; M2 re-measures RTF with `ref_audio` cloning (`infer_batch` takes one `ref_audio`, so it cannot batch segments that use different refs). Sampling via `infer(temperature=...)` (v3 Turbo default `0.8`; no seed parameter): `0.8` for neutral, up to `0.95` scaled by intensity for expressive segments.
- Per segment: retry once on failure; then retry with the voice's neutral form (preset voices: `voice=preset_name` without a ref; clone voices, which have no preset: the clone's `neutral` ref); then with the default narrator preset; record a warning. A segment never blocks the chapter.
- Quality guard per segment (metric defined in the M0 results doc, "S1 female-noise debug"): VieNeu output noise varies per sample and per preset. Metric: mono 48 kHz; 40 ms Hann frames, hop 20 ms; keep frames with RMS ≥ 0.03 and zero-crossing rate ≤ 0.06 (vowel-like); per frame ratio = power(4-12 kHz) / power(0-4 kHz); segment value = median over kept frames. Threshold (starting value, tune in M2): re-synthesize the segment if its median ratio > 2.5 × the voice's baseline, where baseline = the same median measured over the voice's neutral reference audio: for preset voices the preset's own neutral output clip (the M0 base clip, `assets/voice-refs/m0/base/{narrator,male,female}.wav`, measured 0.56 / 0.62 / 0.41 ×1e-3), not a VoxCPM2 ref; for clone voices the clone's `neutral` ref. Baselines are computed once per voice and cached. Max 2 retries; keep the take with the lowest ratio. Segments with no kept frames skip the guard, which includes most whisper segments (their ZCR exceeds 0.06); M2 tunes the threshold on real chapters, including cloned and whisper segments.
- Post-processing per segment: trim leading/trailing silence, loudness-normalize, append an emotion-dependent pause (neutral 250 ms, sad/tender 450 ms, angry/shout 150 ms; paragraph end +200 ms).
- Encoding (spike S2): one long-lived ffmpeg/libopus process per chapter, fed segment PCM (float32 mono 48 kHz) on stdin in order, WebM read from stdout:

  ```
  ffmpeg -hide_banner -loglevel error -f f32le -ar 48000 -ac 1 -i pipe:0 \
    -c:a libopus -b:a 48k -ar 48000 -ac 1 \
    -f webm -live 1 -cluster_time_limit 30000 -cluster_size_limit 50000000 \
    -flush_packets 1 pipe:1
  ```

  `-cluster_size_limit 50000000` is required: with pipe output and the default size limit, ffmpeg cuts clusters at ~32 KiB (the final review measured 25 clusters instead of 4 for 90 s of speech), so `-cluster_time_limit` alone does not control the cut. `-flush_packets 1` makes ffmpeg write each cluster to the pipe promptly instead of buffering it.
- The worker parses the EBML stream from stdout incrementally, uploads `init.webm` (bytes before the first Cluster) first, then each cluster as `seg-{0000}.webm` as soon as it is complete, appends it to `chapter_audio.chunks`, and sets `status='partial'`. Cluster cut points and `start_ms`/`end_ms` are read from the muxed stream (ffmpeg cuts about 19 ms before the limit); the worker never assumes cluster N == text chunk N. All keys use the row's current `{attempt}` (4.3). On completion: produce the seekable `full.webm` by remux (4.3), upload it, then set `full_key`, `duration_ms`, final `segments`, `status='ready'` (fenced by attempt, 5.1). `duration_ms = round(total PCM samples fed to the encoder / 48)`, i.e. the signal length, not the container's buffered end. Only a one-shot offline encode was validated in S2; the incremental pipe path is an M2 exit criterion (8).
- Synthesis order is sequential so the first cluster is ready within seconds of job start.

### 5.7 Scheduler

Every `follow_interval_hours` (default 6): enqueue `check_updates` per followed novel. Handler re-reads the TOC, inserts new chapters with `is_new = true`, enqueues `fetch_chapter` for them, and `synthesize` (priority 20) when `auto_synthesize_new` is on.

### 5.8 Prefetch

When the web app opens or advances to chapter N, it enqueues `fetch_chapter` and `synthesize` (priority 10) for N+1..N+k (`prefetch_count`, default 3), skipping chapters already ready for the current `voice_hash`.

### 5.9 Operations

- `uv run worker` (foreground) or installed as a Windows service with NSSM (documented).
- Requires `ffmpeg` on PATH. First run downloads VieNeu weights.
- `.env`: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, `GEMINI_API_KEY`, `GEMINI_MODELS`, `GEMINI_LIMITS`, `LOCAL_LLM_PATH` (optional), `WORKER_ID`.
- Logs: rotating file `worker/logs/worker.log`, level from env.
- Flag `--fake-tts` produces sine tones of text-proportional length (for E2E tests).

### 5.10 Emotion reference bank

- Default voices (Southern VieNeu presets, owner choice in spike S1): narrator "Đức Trí", male "Thái Sơn", female "Mỹ Duyên". "Kim Thanh" was rejected for a ~5x higher 4-12 kHz / 0-4 kHz energy ratio in vowel frames than the other presets (metric in the M0 results doc, "S1 female-noise debug").
- "Neutral" means the preset voice itself (`infer(voice=preset_name)`), not a VoxCPM2 neutral clip. Neutral refs are not used for preset voices.
- `tools/emotion_refs.ipynb` (Colab/Kaggle GPU): VoxCPM2 controllable cloning generates 3-8 s Vietnamese clips per (voice, emotion), for the narrator, default male, and default female voices.
- Validation basis archived in the repo: `assets/voice-refs/m0/` (3 preset base clips + 18 VoxCPM2 refs used in S1, sha256 in the M0 results doc). The enabled pairs below use exactly these files.
- Emotion refs are enabled only for the five pairs rated 2 in spike S1: narrator/angry, male/angry, male/whisper (enabled), female/happy and female/sad (**provisional**: the female_neutral clone was also rated 2 against the preset, so these ratings are confounded by the VoxCPM2 timbre shift; M4 re-tests them against a clone-from-neutral-ref baseline and disables them if the emotion is not audible beyond that shift). Every other pair (including all `fearful`) uses the preset voice + prosody post-processing.

- Regenerating any ref (notebook re-run, other settings or seed) voids its S1 validation: the pair stays disabled until re-tested with the S1 listening-page method (VoxCPM2 ref, VieNeu preset and VieNeu clone side by side, rated 0/1/2; enable only at 2). New pairs follow the same rule.
- Clips are uploaded via the Settings → Voices page (or the notebook writes them directly to R2) and referenced from `voices.refs`.
- Users may also upload their own clip per emotion. Only voices the owner has rights to may be cloned.

### 6.5 Audio engine

- Primary: `MediaSource` + one `SourceBuffer('audio/webm; codecs="opus"')` in `segments` mode. The player appends `init.webm` once, then the cluster media segments (`seg-*`) in order as they become available, with no `timestampOffset` or append windows; `<audio>` element provides `preservesPitch`, `playbackRate`, seeking, and Media Session integration.
- Duration: if the row is already `ready` when the player opens it, the player sets `mediaSource.duration = duration_ms / 1000` right after `sourceopen` and **before** the first append. It never lowers `duration` once frames are buffered (Chromium throws `InvalidStateError` when `duration` is set below the highest buffered timestamp), and for a `partial` row it leaves `duration` alone and lets `endOfStream()` finalize it after the last cluster is appended. Expected buffered end ≈ `duration_ms` + ~21 ms (variant C measured 30.021 s for a 30.000 s signal); the player must not treat that tail as an error.
- The player watches `chapter_audio` via Realtime; when `attempt` changes it discards the SourceBuffer and reloads the chapter from the new attempt's `init.webm`, resuming at the same **segment index** (not the same time, because a new attempt has different timing).
- When `full_key` exists and MSE errors, fall back to the full file (seekable remux, 4.3).
- Signed URLs (10 min TTL, 7.3.1) from `GET /api/audio/[chapterAudioId]/urls`, which returns URLs for `init_key`, every key in `chunks` (segments, in order) and `full_key` when present, all for the row's current `attempt`; on 403 the player refreshes URLs once.
- Edge TTS fallback: `GET /api/fallback-tts?chapterId=&segment=` streams MP3 for one segment; player plays segments sequentially with a plain `<audio>` element; single voice; nothing persisted.
- Spike S2 outcome (validated in the Claude desktop browser pane, Chromium 152; owner's browser unrecorded; Edge/Firefox untested): independently encoded WebM chunks clicked audibly at boundaries in both `sequence` mode and `segments` mode with offsets + append windows, so they are rejected. Shared-init cluster segments from one continuous encode played with no click at any boundary (sine and speech) and are the chosen design. C was produced by a one-shot offline encode; the incremental pipe encode is validated in M2 (8).

### 7.2 Error handling

| Situation | Behavior |
|---|---|
| Truyenfull markup change | `ParserBroken`: job fails with a clear message; never synthesize empty text |
| Cloudflare block | `SourceBlocked`: backoff retries; source flagged degraded in UI |
| Segment TTS failure | Retry → same voice preset without ref → default narrator preset; warning recorded; chapter continues |
| Worker crash mid-job | Lease expiry requeues; the re-run increments `chapter_audio.attempt`, resets `init_key`/`chunks`/`full_key`/`duration_ms`, and writes under a new `{attempt}` key prefix (4.3, 5.1); a resumed stale run is stopped by attempt fencing (5.1). Re-runs are not reproducible (VieNeu has no seed), so earlier objects are never reused or overwritten; the player reloads on `attempt` change; GC removes abandoned attempts |
| R2 upload failure | Retry with backoff; chapter stays `partial` |
| LLM invalid output | Next strategy in chain |
| Gemini quota | Per-minute wait or per-day model lock; then local LLM; then heuristic |
| Signed URL expiry | Player refreshes once on 403 |
| MSE error | Full-file fallback if ready, else error state with retry |
| Worker offline (`last_seen` > 60 s) | Banner, Edge TTS offer, jobs stay queued |
| Supabase free-tier pause (7 days idle) | Worker heartbeat keeps project active; documented |

UI copy: Vietnamese, sentence case, no raw exception strings, errors say what happened and what to do.

### 7.3.1 Cost and abuse protection (owner requirement, 2026-10-15)

The Cloudflare account behind R2 has the owner's bank card attached, and R2 bills usage beyond the free tier (storage > 10 GB-month, Class A > 1M ops/month, Class B > 10M ops/month) with no hard spending cap. Every milestone must keep a leaked credential or a runaway loop from turning into a bill.

Account level (owner, done once; checked in M1 Task 9 and M6):
- Repository private (a public repo turns any accidental secret commit into a public leak).
- 2FA on Cloudflare, Supabase, GitHub and (later) Vercel.
- Cloudflare usage-based billing notifications for R2 at roughly 80% of each free allowance.
- A card with a low online spending limit (or a virtual card) for Cloudflare.
- R2 bucket stays private: no `r2.dev` public URL, no custom domain; CORS limited to the app origins (M3).
- R2 tokens scoped to the single bucket; worker token read/write, web token read-only; rotate immediately if either leaks.
- The Gemini key's Google project has no billing account attached (free tier only, so overuse fails instead of charging).
- Vercel stays on Hobby (no card); if ever upgraded, spend management is configured before deploying.

Built into the code:
- Storage cap (M2): the worker records the byte size of every object it uploads (`chapter_audio`) and refuses new uploads when the recorded total exceeds `R2_MAX_BYTES` (default 8 GiB). Synthesis jobs then fail with a clear Vietnamese message; nothing is uploaded.
- Write-ops cap (M2): the worker counts its R2 PUTs per calendar month in Postgres and stops uploading above `R2_MAX_PUTS_PER_MONTH` (default 800,000).
- Kill switch (M2): `R2_UPLOADS_ENABLED=false` in `worker/.env` stops all uploads without stopping the worker.
- Queue limits (M2): a database trigger rejects new `jobs` rows when the owner already has 500 `queued` jobs, so a client bug or a stolen session cannot enqueue unbounded synthesis.
- Read-ops control (M3): signed URLs live 10 minutes (not 1 h); audio keys are immutable, so objects are served with `Cache-Control: public, max-age=31536000, immutable` and the browser re-uses them instead of re-reading R2; the signed-URL route handler is rate limited per user (60 requests/minute, counted in Postgres).
- Route rate limits (M3/M5): every route handler that reaches R2 or Edge TTS is authenticated and rate limited; Supabase Auth's own sign-in rate limits stay enabled.
- Lifecycle (M2): an R2 lifecycle rule deletes `_doctor/` probes after 1 day; GC (4.2) removes stale audio.
- Visibility (M5): Settings → Worker shows recorded R2 bytes and monthly PUTs against the caps.
