# AudioTruyen v2 — Design Spec

**Date:** 2026-10-14
**Branch:** `rework/v2`
**Status:** Approved in brainstorming (sections 1-4), pending written-spec review
**Supersedes:** all specs dated 2026-03-xx (v1 architecture is retired)

---

## 1. Goals and constraints

AudioTruyen v2 is a **private, single-user** web app for reading and listening to Vietnamese web novels at the same time ("read-along"), with **multi-voice, emotion-aware narration** generated by a **self-hosted TTS model**.

### Decisions locked during brainstorming

| Topic | Decision |
|---|---|
| Audience | One user (the owner). Private app, sign-up disabled. Not a public distribution service. |
| Primary usage | Desktop, reading while listening. Sentence/segment highlight is the core experience. PWA/offline is a non-goal. |
| Voice | Multi-voice: narrator + per-character dialogue voices (male/female defaults, per-character overrides). |
| Speaker attribution | Three pluggable strategies, chained: cloud LLM (Gemini free tier) → local LLM (llama.cpp, CPU) → heuristic. |
| Emotion | Layered: LLM labels emotion per segment → VieNeu clones from a per-emotion reference clip bank → non-verbal tags → prosody post-processing. Verified by a spike before building. |
| TTS engine | VieNeu-TTS v3 Turbo (Apache-2.0), local, CUDA when available else ONNX CPU. |
| Audio storage | Cloudflare R2. Fallback when worker is offline: Microsoft Edge TTS, single voice, not persisted. |
| Sources | `SourceAdapter` interface; v2 ships the truyenfull adapter only. |
| Architecture | Approach A: Supabase as hub, worker makes **outbound connections only**. |
| Reader layout | Layout A: focused reading column, drawers for TOC and cast, docked player bar. |
| Theming | Fully user-customizable colors (6 seed colors, derived tokens), presets, reading typography controls. |
| Extra features | Pronunciation lexicon, sleep timer + speed, follow novels for new chapters, bookmarks + notes + listening stats. |
| Hosting | Vercel (web), Supabase free (DB/auth/realtime), R2 free (audio), owner's Windows laptop (worker). |

### Hardware constraint

Worker host: Windows 11 laptop, NVIDIA GTX 1650 Max-Q **4 GB VRAM**. Only one model may hold VRAM at a time. The local LLM runs on CPU. VieNeu v3 Turbo peaks around 1.1 GB VRAM and runs ~2x realtime on CPU, so the whole pipeline also works without a GPU.

### Non-goals (v2)

- Public multi-user service, sign-up, sharing.
- Mobile-first UI, PWA install, offline downloads, Web Push.
- Word-accurate forced alignment (word highlight is interpolated).
- EPUB/TXT import (the adapter interface leaves room for it later).
- Real-time conversational voice agents. Dograh and Pipecat were evaluated: they orchestrate STT→LLM→TTS for live calls and do not provide Vietnamese narration, so they are not used.

## 2. Research findings that shaped the design

### 2.1 Truyenfull "locked chapters"

Verified on 2026-10-13 against `truyenfull.live`:

- The server returns the **full chapter text** inside `#chapter-c` for every chapter (tested chapters 1, 2, 349, 350; ~6,200-6,600 chars each).
- The lock is purely client-side: `static.truyenfull.live/js/minify.js` hides `#chapter-c` and shows `#ads_click_view_chapter` when the cookie `truyenfull_cf_ad_content` is absent and `chapter_num >= 2`. Clicking the ad sets the cookie for 10 minutes.
- A server-side HTML parser therefore never encounters the lock. No interaction or circumvention logic is needed.
- The chapter body ends with SEO junk (`truyen full, truyenfull, truyenfullvn, truyenfulllive ...`) that must be stripped.
- Text contains obfuscated words such as `c.h.ử.i` that must be normalized.
- Novel pages expose `<input id="truyen-id" value="...">`; chapter URLs follow `/{slug}/chuong-{n}/`.
- The page embeds Cloudflare Turnstile. Residential IP requests return 200; datacenter IPs (Vercel) may be challenged. **All scraping runs in the worker.**

Personal-use note: reading the HTML skips the site's ad monetization. This is acceptable only because the app is private and single-user.

### 2.2 TTS model selection

| Model | License | Vietnamese | Fit for 4 GB | Emotion control | Verdict |
|---|---|---|---|---|---|
| VieNeu-TTS v3 Turbo | Apache-2.0 | Native, 3 dialects, 23-25 presets, cloning from 3-8 s | Yes (~1.1 GB VRAM; ONNX CPU ~2x realtime) | Experimental tags `[cười]` `[thở dài]` `[hắng giọng]`; style follows the reference clip | **Chosen** |
| VoxCPM2 | Apache-2.0 | Official, 30 languages | No (~8 GB VRAM) | Voice Design from text description, style tags | Used **once** offline (Colab/Kaggle) to generate emotion reference clips |
| F5-TTS Vietnamese | CC-BY-NC | Yes | Borderline | Via reference | Rejected (non-commercial, heavier) |
| Fish Audio S2 Pro | Non-commercial | Yes | No (4B + 400M) | Best | Rejected |
| V-TTS (Valtec) | Open | Yes, 74.8M params | Yes, CPU | Limited | Noted as emergency fallback only |

### 2.3 Gemini free tier

- Limits are per **project**, not per key; RPD resets at midnight **Pacific time**.
- Free-tier quotas are low and volatile (Flash cut to ~20 RPD in Dec 2025; Flash-Lite reported ~15 RPM / 500 RPD on 2026-10-13). 429s can occur below the displayed quota.
- Model IDs change over time. The worker must discover available models at startup, never hardcode a single ID.

                │ RLS) + Realtime               │ in Vercel env only)
┌───────────────▼──────────────┐      ┌────────▼────────────────┐
│ Supabase (ap-southeast-1)    │      │ Cloudflare R2 (private)  │

└───────────────▲──────────────┘               │ S3 PUT
                │ outbound only (service role)  │
┌───────────────┴───────────────────────────────┴────────────────┐

## 4. Data model (Supabase Postgres)

All tables have `user_id uuid not null references auth.users` (except worker-only tables), RLS enabled, policy "authenticated users own rows only", anon denied. The worker uses the service-role key and bypasses RLS.

```sql
novels (
  id uuid pk, user_id, source text,            -- 'truyenfull'
  source_novel_id text, url text, slug text,
  title text, author text, cover_url text, description text,
  status text,                                 -- 'ongoing' | 'completed' | null
  chapter_count int, followed bool default false,
  auto_synthesize_new bool default true,
  last_checked_at timestamptz, created_at, updated_at,
  unique (user_id, source, source_novel_id)
)

chapters (
  id uuid pk, novel_id fk, index int, title text, url text,
  text text null, text_hash text null, fetched_at timestamptz null,
  is_new bool default false,                   -- set by scheduler, cleared on open
  unique (novel_id, index)
)

characters (
  id uuid pk, novel_id fk, name text, aliases text[],
  gender text check in ('male','female','unknown'),
  voice_id uuid null fk voices, color text null,  -- null = auto from theme
  manual bool default false,                   -- true = never overwritten by analysis
  unique (novel_id, name)
)

voices (
  id uuid pk, name text, kind text check in ('preset','clone'),
  preset_name text null,                       -- VieNeu preset id
  refs jsonb,                                  -- { "neutral": "r2-key", "angry": "r2-key", ... }
  gender text, is_default_narrator bool, is_default_male bool, is_default_female bool
)

lexicon (
  id uuid pk, novel_id uuid null,              -- null = global
  pattern text, replacement text, is_regex bool, enabled bool,
  position int                                 -- application order
)

chapter_analysis (
  chapter_id fk, text_hash text, strategy text, strategy_version int,
  segments jsonb, created_at,
  primary key (chapter_id, text_hash, strategy_version)
)

chapter_audio (
  id uuid pk, chapter_id fk, voice_hash text,
  status text check in ('queued','partial','ready','failed'),
  provider text,                               -- 'vieneu'
  chunks jsonb,                                -- [{ key, start_ms, end_ms }]
  full_key text null, duration_ms int null,
  segments jsonb,                              -- see 4.1
  warnings jsonb, created_at, updated_at,
  unique (chapter_id, voice_hash)
)

jobs (
  id uuid pk, type text check in ('search','fetch_novel','fetch_chapter','synthesize','check_updates'),
  payload jsonb, priority int,                 -- 0 interactive, 10 prefetch, 20 background
  status text check in ('queued','running','done','failed','cancelled'),
  attempts int default 0, max_attempts int default 3,
  run_after timestamptz default now(),
  lease_until timestamptz null, worker_id text null,
  result jsonb null, error text null, created_at, updated_at
)

worker_status (worker_id text pk, last_seen timestamptz, version text,
               device text, queue_depth int, current_job uuid null)

llm_usage (model text, day_pt date, requests int, tokens int,
           locked_until timestamptz null, primary key (model, day_pt))

progress (novel_id pk-part, user_id pk-part, chapter_id, segment_index int,
          position_ms int, updated_at)
listened_chapters (chapter_id, user_id, finished_at)
bookmarks (id, chapter_id, segment_index, quote text, note text, created_at)
listen_sessions (id, chapter_id, started_at, seconds int)
settings (user_id pk, data jsonb, updated_at)  -- see 7.1 / 6.4
```

`claim_job(worker_id text, lease_seconds int)` is a SQL function: selects the first `queued` job with `run_after <= now()` ordered by `priority, created_at`, `FOR UPDATE SKIP LOCKED`, sets `running`, `lease_until`, `worker_id`, increments `attempts`, returns it. A companion `requeue_expired_jobs()` resets `running` jobs whose `lease_until < now()`.

### 4.1 Segment schema

```json
{
  "i": 12,
  "kind": "narration" | "dialogue",
  "src": [1043, 1121],          // char range in ORIGINAL chapter text (for highlight)
  "speaker": "Lâm Phong" | null,
  "gender": "male" | "female" | "unknown",
  "emotion": "neutral" | "happy" | "sad" | "angry" | "fearful" | "whisper" | "shout" | "tender",
  "intensity": 0.0-1.0,
  "tags": [{ "at": 34, "tag": "[cười]" }],
  "voice_id": "uuid",
  "start_ms": 81234, "end_ms": 85610
}
```

### 4.2 voice_hash

`sha256(narrator_voice_id, default_male_id, default_female_id, sorted(character→voice overrides for this novel), lexicon_version, pipeline_version)[:16]`. Changing voices or the lexicon produces a new hash; old audio is kept until garbage-collected (R2 objects whose `chapter_audio` row is older than 30 days and not the current hash).

### 4.3 R2 key layout

```
audio/{novel_id}/{chapter_id}/{voice_hash}/chunk-{0000}.webm
audio/{novel_id}/{chapter_id}/{voice_hash}/full.webm
voices/{voice_id}/{emotion}.wav
```

## 5. Worker

### 5.1 Job loop

- On start: register in `worker_status`, discover Gemini models, load VieNeu lazily on first `synthesize`.
- Wake sources: Supabase Realtime subscription on `jobs` inserts + 30 s polling fallback.
- Heartbeat every 15 s: updates `worker_status`, extends `lease_until` of the current job, calls `requeue_expired_jobs()`.
- One job at a time. Lease 5 min, extended by heartbeat.
- Failure: `attempts < max_attempts` → `queued` with `run_after = now() + 2^attempts min`; else `failed` with a human-readable `error`.
- `synthesize` jobs whose `voice_hash` no longer matches the current settings are marked `cancelled` without work.

### 5.2 SourceAdapter

```python
class SourceAdapter(Protocol):
    id: str                                   # 'truyenfull'
    def matches(self, url: str) -> bool: ...
    def search(self, query: str) -> list[NovelSummary]: ...
    def novel(self, url: str) -> NovelDetail: ...          # metadata + full TOC
    def chapter(self, url: str) -> ChapterContent: ...
```

Truyenfull adapter:
- `httpx` with a desktop browser User-Agent, ~1 req/s with 0.3-0.8 s jitter, retries with backoff on 5xx/timeouts.
- TOC: paginate the novel's chapter list until exhausted; implementation must inspect the live pagination (page links or AJAX) and record fixtures.
- Chapter: parse `#chapter-c`, drop `#ads-chapter-top` and any `ads-*` descendants, convert `<br>` to line breaks, strip the trailing SEO keyword block.
- Validation: raise `ParserBroken` if text is empty or under 500 chars for a chapter whose title is present; raise `SourceBlocked` on Cloudflare challenge markers or HTTP 403/503 with challenge body.

### 5.3 Text pipeline

1. **Normalize** (TTS input only; display text stays original): Unicode NFC; de-obfuscate dotted words (`c.h.ử.i` → `chửi`, regex for single Vietnamese letters separated by dots); numbers, dates, units, abbreviations via VietNormalizer; then lexicon rules (global by `position`, then novel-level). Each transformation keeps an offset map back to original text.
2. **Segment**: split paragraphs; within paragraphs separate dialogue (`"..."`, `“...”`, lines starting with `-`/`–`) from narration; split segments over ~250 chars at sentence boundaries. Each segment records its `src` range in original text.
3. **Analyze** (speaker, gender, emotion, intensity, non-verbal tags) via strategy chain (5.4). Cached in `chapter_analysis`.
4. **Resolve voice**: narration → narrator voice; dialogue → character's voice, else default by gender, else default narrator-alt. Then pick the voice's reference clip for the segment's emotion; fall back to `neutral`.

### 5.4 Speaker/emotion strategies

```python
class SpeakerStrategy(Protocol):
    name: str; version: int
    def analyze(self, segments: list[Segment], roster: list[Character]) -> list[SegmentLabel]: ...
```

Chain order configurable in settings (default: `gemini → local_llm → heuristic`). A strategy result is accepted only if it passes JSON-schema validation and covers every segment id; otherwise the next strategy runs.

- **gemini**: one request per chapter. Input: numbered segments + compact roster. Output: compact JSON array `[[i, speaker, gender, emotion, intensity, tags]]` plus `new_characters`. Uses structured output (response schema) where the model supports it.
- **local_llm**: llama.cpp (via `llama-cpp-python`) on CPU, Qwen-class 1.5-3B instruct GGUF Q4, same prompt and schema, processed in windows of ~40 segments. Model file path in `.env`; strategy is skipped if absent.
- **heuristic**: dialogue speaker from adjacent attribution verbs (`nói`, `hỏi`, `quát`, `gầm lên`, `thì thầm`, ...) and the nearest name or pronoun (`anh/hắn/ông` → male, `cô/nàng/bà` → female); emotion from verb lexicon and punctuation (`!` → intensity up, `...` → sad/tender, `?` neutral). Unknown → `unknown` gender, `neutral`.

Roster merge: new characters inserted; existing non-`manual` rows may update `gender` only when the new label has higher confidence; `manual` rows are never changed.

### 5.5 Gemini client and rate limiting

- Models from `GEMINI_MODELS` env (ordered, default: newest Flash-Lite, then newest Flash), filtered at startup by `models.list`.
- Limits per model from `GEMINI_LIMITS` env (`rpm`, `rpd`), applied at **80%** of the configured values.
- `llm_usage` row per `(model, day_pt)` persists counts across restarts. Minimum spacing between requests = `60 / effective_rpm` seconds.
- 429 handling: if the error's quota metric is per-minute, sleep for `RetryInfo.retryDelay` (default 60 s) and retry once; if per-day, set `locked_until` to next midnight Pacific and move to the next model. All models locked → next strategy.
- Budget priority: jobs with priority 0-10 may use Gemini freely; priority 20 (background/new chapters) only when today's remaining budget is above 50%.
- API key lives only in `worker/.env` (`GEMINI_API_KEY`), never committed, never sent to the web app.

### 5.6 TTS and audio

```python
class TTSProvider(Protocol):
    name: str
    def synthesize(self, text: str, voice: VoiceRef, emotion: str, intensity: float,
                   tags: list[Tag]) -> np.ndarray: ...   # float32 mono @ provider rate
```

- `vieneu` provider: VieNeu v3 Turbo; device auto (`cuda` if available, else ONNX CPU). Clones from the selected reference clip. Temperature `0.8` for neutral, up to `0.95` scaled by intensity for expressive segments. Non-verbal tags inserted at `tags[].at`.
- Per segment: retry once on failure; then retry with the `neutral` ref; then with the default narrator preset; record a warning. A segment never blocks the chapter.
- Post-processing per segment: trim leading/trailing silence, loudness-normalize, append an emotion-dependent pause (neutral 250 ms, sad/tender 450 ms, angry/shout 150 ms; paragraph end +200 ms).
- Chunking: concatenate segments in order into ~30 s chunks (segment boundaries respected), encode each as standalone WebM/Opus 48 kbps via ffmpeg, upload immediately, append to `chapter_audio.chunks`, set `status='partial'`. On completion, concatenate into `full.webm`, set `ready`, `duration_ms`, final `segments`.
- Synthesis order is sequential so the first chunk is ready within seconds of job start.

### 5.7 Scheduler

Every `follow_interval_hours` (default 6): enqueue `check_updates` per followed novel. Handler re-reads the TOC, inserts new chapters with `is_new = true`, enqueues `fetch_chapter` for them, and `synthesize` (priority 20) when `auto_synthesize_new` is on.

### 5.8 Prefetch

When the web app opens or advances to chapter N, it enqueues `fetch_chapter` and `synthesize` (priority 10) for N+1..N+k (`prefetch_count`, default 3), skipping chapters already ready for the current `voice_hash`.

### 5.9 Operations

- `uv run worker` (foreground) or installed as a Windows service with NSSM (documented).
- Requires `ffmpeg` on PATH. First run downloads VieNeu weights.
- `.env`: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, `GEMINI_API_KEY`, `GEMINI_MODELS`, `GEMINI_LIMITS`, `LOCAL_LLM_PATH` (optional), `WORKER_ID`.
- Logs: rotating file `worker/logs/worker.log`, level from env.
- Flag `--fake-tts` produces sine tones of text-proportional length (for E2E tests).

### 5.10 Emotion reference bank

- `tools/emotion_refs.ipynb` (Colab/Kaggle GPU): VoxCPM2 Voice Design generates 3-8 s Vietnamese clips per (voice, emotion) from text descriptions, for the narrator, default male, and default female voices.
- Clips are uploaded via the Settings → Voices page (or the notebook writes them directly to R2) and referenced from `voices.refs`.
- Users may also upload their own clip per emotion. Only voices the owner has rights to may be cloned.

## 6. Web app

### 6.1 Stack

Next.js 16 App Router, React 19, TypeScript, Tailwind v4 (`@tailwindcss/postcss`), Radix primitives through shadcn/ui components owned in-repo and restyled to tokens, Phosphor icons (lucide removed), `motion/react`, TanStack Query, Zustand (player state only), `@supabase/ssr`, `next/font` (Be Vietnam Pro, Literata, Noto Serif, Lexend; `vietnamese` subsets).

Design read: personal desktop read-along app for one Vietnamese reader, calm text-first language. Dials: `DESIGN_VARIANCE 4`, `MOTION_INTENSITY 4`, `VISUAL_DENSITY 4`. Motion only communicates state (highlight follow, drawer open/close, generation progress) and collapses under `prefers-reduced-motion`.

### 6.2 Routes

| Route | Purpose |
|---|---|
| `/login` | Email + password sign-in (sign-up disabled in Supabase) |
| `/` | Library: "Nghe tiếp" resume card, followed novels grid (cover, progress, new-chapter badge), recently added |
| `/novel/[id]` | Metadata, follow toggle, virtualized TOC with per-chapter status (text cached, audio ready, listened), tabs: Nhân vật, Từ điển phát âm |
| `/read/[novelId]/[chapterIndex]` | Reader (layout A) |
| `/bookmarks` | Bookmarked segments with notes, jump to position |
| `/stats` | Listening time per day, streak, chapters finished, time per novel |
| `/settings/*` | `giao-dien`, `giong-doc`, `phan-tich`, `phat-am`, `worker`, `tai-khoan` |

Middleware redirects unauthenticated requests to `/login`.

Command palette (`Ctrl+K`): search library and chapters, run commands, paste a truyenfull URL to add a novel (enqueues `fetch_novel`, priority 0), search truyenfull (enqueues `search`, result returned through the job row via Realtime).

### 6.3 Reader (layout A)

- Top bar: novel title, chapter, cast and settings buttons; auto-hides while playing, reappears on pointer movement near the top.
- Left drawer: TOC. Right drawer: cast (characters with gender, voice, color; edits set `manual = true` and trigger re-synthesis).
- Reading column: original text, configurable font/size/line-height/width/paragraph spacing/alignment. Dialogue segments show a small speaker label in the speaker color. Click a label → popover "Ai nói câu này?" to reassign; saves an override and re-enqueues synthesis.
- Click any segment → play from it. Current segment highlighted; optional interpolated word highlight.
- Auto-scroll keeps the current segment in the upper third. Manual scroll pauses auto-scroll and shows a "Về chỗ đang đọc" pill.
- Player bar: play/pause, prev/next segment, prev/next chapter, speaker-colored timeline (hover preview of the segment text, click to seek, generated vs pending ranges distinguished), elapsed/total, speed 0.75-2x (pitch preserved), sleep timer (15/30/45/60 min, end of chapter), volume, ambient track picker.
- Generation states: queued (position in queue), partial (playable up to generated range), ready, failed (error + retry), worker offline (banner with last-seen time + "Nghe tạm bằng Edge TTS").
- Progress saved (debounced 2 s and on pause/unload) to `progress`; chapter end writes `listened_chapters` and auto-advances.
- Keyboard: `Space` play/pause, `←/→` segment, `Shift+←/→` chapter, `[`/`]` speed, `B` bookmark, `T` TOC, `C` cast, `Ctrl+K` palette, `?` shortcut sheet.

### 6.4 Theming

- Semantic CSS variables: `--bg`, `--surface`, `--surface-raised`, `--text`, `--text-muted`, `--border`, `--border-strong`, `--accent`, `--accent-contrast`, `--highlight`, `--highlight-word`, `--focus`.
- User edits 6 seeds: background, raised surface, text, muted text, accent, highlight. Others derived with `color-mix(in oklch, ...)`.
- Live WCAG contrast readout (text/bg, muted/bg, text/highlight, accent-contrast/accent); warning below 4.5:1 (3:1 for large text).
- Presets: Giấy (light, cool), Đêm (dark charcoal), OLED (near-black, not `#000`), Sepia (reading mode), Rừng (deep green dark). Default: follow `prefers-color-scheme` between Giấy and Đêm.
- Multiple saved custom themes; JSON import/export.
- Speaker colors auto-generated in OKLCH with lightness/chroma fixed per theme and hue spread per character; per-character override.
- Stored in `settings.data.appearance`, cached in `localStorage`; a blocking inline script in `layout.tsx` applies variables before first paint (no flash).

### 6.5 Audio engine

- Primary: `MediaSource` + `SourceBuffer('audio/webm; codecs="opus"')` in `sequence` mode, appending chunks as they become available; `<audio>` element provides `preservesPitch`, `playbackRate`, seeking, and Media Session integration.
- When `full_key` exists and MSE errors, fall back to the full file.
- Signed URLs (1 h TTL) from `GET /api/audio/[chapterAudioId]/urls`; on 403 the player refreshes URLs once.
- Edge TTS fallback: `GET /api/fallback-tts?chapterId=&segment=` streams MP3 for one segment; player plays segments sequentially with a plain `<audio>` element; single voice; nothing persisted.
- Spike S2 must confirm gapless sequence-mode playback of independently encoded WebM chunks in Chrome/Edge/Firefox; if it fails, chunks are encoded as WebM media segments sharing one init segment.

### 6.6 Settings pages

- Giao diện: theme presets, seed editor, contrast readout, reading typography, import/export.
- Giọng đọc: narrator / default male / default female selection from voice bank, preview playback, emotion reference status per voice, clip upload.
- Phân tích: strategy order, today's Gemini usage per model vs limits, local LLM status.
- Phát âm: global lexicon editor (plain or regex), test field with "Nghe thử" (enqueues a tiny priority-0 synth job).
- Worker: online status, device, queue (cancel/retry jobs), `prefetch_count`, `follow_interval_hours`, `auto_synthesize_new` default.
- Tài khoản: email, password change, sign out.

## 7. Cross-cutting

### 7.1 Settings document

`settings.data` JSON: `{ appearance, reading, player: { speed, ambientTrack, ambientVolume, wordHighlight }, voices: { narrator, male, female }, analysis: { order: [...] }, worker: { prefetchCount, followIntervalHours, autoSynthesizeNew } }`. Validated with zod on the web side and pydantic on the worker side.

### 7.2 Error handling

| Situation | Behavior |
|---|---|
| Truyenfull markup change | `ParserBroken`: job fails with a clear message; never synthesize empty text |
| Cloudflare block | `SourceBlocked`: backoff retries; source flagged degraded in UI |
| Segment TTS failure | Retry → neutral ref → default preset; warning recorded; chapter continues |
| Worker crash mid-job | Lease expiry requeues; deterministic chunk keys make re-runs idempotent |
| R2 upload failure | Retry with backoff; chapter stays `partial` |
| LLM invalid output | Next strategy in chain |
| Gemini quota | Per-minute wait or per-day model lock; then local LLM; then heuristic |
| Signed URL expiry | Player refreshes once on 403 |
| MSE error | Full-file fallback if ready, else error state with retry |
| Worker offline (`last_seen` > 60 s) | Banner, Edge TTS offer, jobs stay queued |
| Supabase free-tier pause (7 days idle) | Worker heartbeat keeps project active; documented |

UI copy: Vietnamese, sentence case, no raw exception strings, errors say what happened and what to do.

### 7.3 Security

- Web uses only the anon key + user session; all access through RLS.
- Service-role key, R2 credentials for writing, and the Gemini key exist only on the worker. R2 credentials on Vercel are read-only (presign GET only).
- Sign-up disabled; single user created in the Supabase dashboard.
- `.env` files are gitignored (root pattern `.env` already covers `worker/.env` and `web/.env*`).

### 7.4 Testing

- Worker (`pytest`): truyenfull fixtures (saved real HTML for novel page, TOC pages, chapters); golden tests for normalization and segmentation (dotted obfuscation, dash-led dialogue, nested quotes, long sentences); schema validation for strategy output with a fake LLM; rate limiter with a fake clock and simulated 429 types; `claim_job` concurrency against local Supabase (`supabase start`); audio chunking timing math.
- Web (`vitest`): theme derivation and contrast math, timeline/segment mapping, word-highlight interpolation, settings schema.
- E2E (`playwright`): sign-in, add novel via pasted URL, open chapter, play, highlight advances, bookmark, theme change. Runs against local Supabase with the worker in `--fake-tts` mode.
- CI (GitHub Actions): web lint, typecheck, vitest, build; worker ruff, pytest (unit tier; DB tier when Supabase CLI is available in CI).

### 7.5 Deployment

- Vercel project root `web/`, region `sin1`, preview deploys per PR. Env: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `R2_ACCOUNT_ID`, `R2_READ_ACCESS_KEY_ID`, `R2_READ_SECRET_ACCESS_KEY`, `R2_BUCKET`.
- Supabase project in `ap-southeast-1`; migrations via Supabase CLI; Realtime enabled for `jobs`, `chapter_audio`, `worker_status`.
- R2 bucket private; two API tokens (worker read/write, Vercel read-only).

## 9. Risks

| Risk | Mitigation |
|---|---|
| Truyenfull changes domain/markup or tightens Cloudflare | Adapter isolation, fixtures, `ParserBroken`/`SourceBlocked` surfacing, adapter interface for new sources |
| Gemini free tier cut further | Rate limiter at 80%, per-chapter single request, cascade to local LLM/heuristic |
| VieNeu emotion transfer weak | Spike S1 first; provider abstraction |
| Laptop off for long periods | Web stays usable for cached content; Edge fallback; Supabase kept alive only while worker runs (documented) |
| R2 free 10 GB exhausted | ~2 MB/chapter at 48 kbps ≈ 5,000 chapters; GC of stale voice_hash audio after 30 days; usage shown in Settings → Worker |
