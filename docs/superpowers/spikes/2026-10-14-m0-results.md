Diagnosis (not fixed, per spike scope): `.venv-cpu` has onnxruntime 1.31.0 and huggingface_hub 2.2.0. hub 2.x stores blobs in a shared, sharded `hub/blobs/<2 chars>/<sha>` layout and the snapshot files are symlinks into it, so `vieneu_prefill.onnx` and its external data file `vieneu_backbone_shared.data` resolve into different directories. onnxruntime 1.31 rejects external data that resolves outside the model's directory. `.venv-gpu` (huggingface_hub 0.36.2, per-repo blob folder) uses the torch path and is unaffected. Plausible fixes for M2 or a re-run: pin `huggingface_hub<1.0` in the CPU environment, pin an older onnxruntime, or download the ONNX folder with `local_dir` (real files, no symlinks).
