# M3 Web Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner can open the web app, add a truyenfull novel, browse its chapters, open a chapter, press play and listen while the current segment is highlighted and followed, with progress saved and the next chapters prefetched, inside the 7.3.2 performance budget.

**Architecture:** Server Components render every page, including the chapter text (one `<span data-seg>` per analysis segment), so the reading column ships no JavaScript. One client island per page handles interaction. In the reader that island is a player controller: it lazy-loads the MSE engine and the Supabase browser client (Realtime) on first play, fetches 10-minute signed R2 URLs from a rate-limited route handler, appends `init.webm` plus cluster segments to one SourceBuffer, and drives highlight and auto-scroll from `audio.currentTime` through direct DOM updates rather than React renders. Jobs are enqueued by server actions under the user's session, and RLS plus the M2a `jobs_guard_write` trigger enforce the rules. One small worker change writes segment timings with every partial update, so highlight works while a chapter is still being generated.

**Tech Stack:** Next.js 16.4 App Router, React 19.3, TypeScript, Tailwind v4, `@supabase/ssr` 0.12 / `supabase-js` 2.117, zod 4, `aws4fetch` (SigV4 presign, server only), `@phosphor-icons/react`, vitest 5 (+ browser mode with `@vitest/browser-playwright`, Chromium), Supabase Postgres + pgTAP, Python 3.12 worker (one change).

**Spec:** `docs/superpowers/specs/2026-10-14-audiotruyen-v2-design.md`. The sections that matter are 4, 4.1, 4.3, 5.1, 5.8, 6.1-6.5, 7.2, 7.3.1, 7.3.2, 7.4 and 8 (M3 row). Read the spec sections a task names before starting it.

## Global Constraints

- Next.js 16 uses `proxy.ts`, not `middleware.ts`. Server Components by default. Client components only for interactive islands. Heavy client modules (MSE engine, Supabase browser client) are loaded with dynamic `import()` when first needed.
- The web uses only the anon key plus the user session (RLS). R2 credentials on the web are read-only, server-only (`import "server-only"`), never `NEXT_PUBLIC_*`: `R2_ACCOUNT_ID`, `R2_READ_ACCESS_KEY_ID`, `R2_READ_SECRET_ACCESS_KEY`, `R2_BUCKET`, plus the optional dev overrides `R2_ENDPOINT_URL` and `R2_REGION` (default `auto`).
- First-load client JS, gzip: library `/` and novel `/novel/[id]` < 150 KB; reader `/read/[novelId]/[chapterIndex]` < 220 KB including the player. The measured baseline on 2026-11-03 is 132 KB on `/` with no features, so every client byte counts.
- Production targets (Vercel `sin1`, M6): TTFB p75 < 300 ms; LCP < 1.5 s; INP < 100 ms; CLS < 0.05. Playback starts < 1.5 s after pressing play on a `ready` chapter. Highlight stays within 100 ms of the audio.
- Signed URLs live 10 minutes. The signed-URL route handler is authenticated and rate limited at 60 requests/minute per user, counted in Postgres. Every route handler that reaches R2 is authenticated and rate limited.
- No new dependency without checking its bundle cost. M3 adds only:
  - Runtime: `aws4fetch` (server), `@phosphor-icons/react` (one import per icon).
  - Dev: `@vitest/browser-playwright`, `playwright`.
  - Pin versions that are at least two weeks old and match the installed vitest major.
- UI copy is Vietnamese and sentence case. No raw exception strings. Errors say what happened and what to do.
- Motion only communicates state. It collapses under `prefers-reduced-motion`, and smooth scrolling becomes instant there.
- Fonts come from `next/font` with only the `vietnamese` and `latin` subsets: Be Vietnam Pro (UI, already loaded) and Literata (reading column, loaded only by the reader layout).
- Theme tokens are CSS variables (spec 6.4). Add `--border-strong`, `--highlight` and `--highlight-word` to both presets in `web/app/globals.css`. Never hard-code colors in components.
- `src` offsets in segments are Python code-point indices. Convert them to UTF-16 before slicing JavaScript strings (spec 4.1).
- MSE rules (spec 6.5):
  - Use one SourceBuffer, `audio/webm; codecs="opus"`, `mode = "segments"`, with no `timestampOffset` and no append windows.
  - For a row that is `ready` when opened, set `mediaSource.duration = duration_ms / 1000` after `sourceopen` and before the first append.
  - Never lower `duration` once frames are buffered. For a `partial` row, call `endOfStream()` after the last cluster.
  - A buffered end of about `duration_ms + 21 ms` is normal.
  - When `attempt` changes, reload from the new `init.webm` at the same segment index.
  - Fall back to `full_key` on an MSE error.
  - Refresh signed URLs once on a 403.
- Database rules (CLAUDE.md):
  - Applied migrations are never edited; changes go in a new file.
  - Every new table enables RLS and gets explicit policies.
  - Every new function revokes execute from `public, anon, authenticated`, then grants only the intended roles.
  - `security definer` functions use `set search_path = ''` and fully qualified names, and must never write `jobs` when exposed to `authenticated`.
  - pgTAP covers every new table and function.
- Worker: every R2 upload still goes through `GuardedStorage.put` (Task 3 adds no upload).
- Commands (from `web/`): `npm test` (vitest unit), `npm run test:browser` (vitest browser, Chromium), `npm run lint`, `npm run typecheck`, `npm run build`, `npm run check:bundle`.
  - Database, from the repo root: `npx --yes supabase@2.121.0 test db`.
  - Worker, from `worker/`: `uv run pytest -q`, `uv run ruff check . && uv run ruff format --check .`.
- Branch `rework/m3` off `main`. Merge to `main` locally and push at the end (owner preference, no PR).

## Decisions (controller rulings; change only with the owner)

Each ruling gives the decision, why, and what it costs if wrong.

1. **Synthesis and prefetch start on the first play in a chapter, not on open.** Spec 5.8 says "opens".
   - Why: opening chapters to read or browse would otherwise spend GPU time and about 6 MB of R2 per chapter (plus 3 prefetches each).
   - Cost if wrong: the first play of an unprepared chapter waits about 5 s for the first cluster (that cost exists either way).
2. **The TOC is paginated server-side (100 per page, `?trang=`), not virtualized.**
   - Why: zero client JS on the novel page. Spec 7.3.2 allows paginate or virtualize.
   - Cost if wrong: one click per 100 chapters.
3. **No TanStack Query, Zustand, motion, Radix or shadcn in M3.** Drawers use native `<dialog>`. Player state is a small external store read with `useSyncExternalStore`.
   - Why: the 18 KB of headroom on library pages.
   - Cost if wrong: M5 adds them when a feature needs them.
4. **Highlight during `partial` needs segment timings in partial rows.** Task 3 changes the worker so every progress update writes `segments` (timed so far).
   - Without it, the most common first listen (a chapter still generating) has no highlight.
5. **Deferred to M4/M5 per spec 8:**
   - M4: cast drawer and speaker labels.
   - M5: word highlight, ambient tracks, sleep timer, bookmarks (`B`), command palette (`Ctrl+K`), Edge TTS button, theme customizer and blocking theme script, settings pages, follow toggle.
   - M3 keeps the keyboard map free for them.
6. **Lighthouse runs on a local production build (`next build && next start`).** Vercel does not exist until M6, which repeats the run on the deployment.
7. **`proxy.ts` uses `getClaims()`.**
   - Production: the owner enables asymmetric JWT signing keys (owner step O2), so claims verify locally.
   - Local Supabase keeps HS256, where `getClaims()` falls back to a `getUser()` round trip. The behavior is identical.
   - Not changing local signing keys avoids touching the keys the worker DB tests use.
8. **Covers use `next/image` with `unoptimized`.** The Vercel optimizer would fetch truyenfull images from a datacenter IP, which may be Cloudflare-challenged (spec 2.1). `width` and `height` are always set (CLS).
9. **Signed URLs use a 5-minute windowed `X-Amz-Date` with `X-Amz-Expires=600`.**
   - The same key signed within one window yields the same URL, so `Cache-Control: immutable` objects are reused from the browser cache.
   - Every URL stays valid for at least 5 minutes after it is handed out.
10. **An "Thêm truyện" form on the library enqueues `fetch_novel`.** The command palette is M5; without the form the web cannot add novels.
11. **Web Vitals samples are stored in M3; Settings → Worker shows them in M5.**
12. **Rate-limit buckets are fixed inside SQL** (`audio_urls` 60/60 s, `vitals` 30/60 s). A client calling the RPC directly cannot pick a window that resets the route's counter.

## Review Focus

These are inputs the spec implies that are most likely to break the reader, most likely first. Each has a test in the task named in parentheses.

1. **Audio made from an older chapter text** (`chapter_audio.text_hash` ≠ `chapters.text_hash`, or null) must be treated as absent: never played against the new text, and re-synthesized on play (Task 9).
2. **Segments without timings.** Stored segments may skip indices (no-text segments), and timings may not exist yet during `partial`.
   - Highlight skips them.
   - Clicking such a segment plays from the next timed segment, or waits for it while generation runs (Task 10).
3. **A signed URL expiring mid-chapter.** A 403 on a later cluster refreshes the manifest once and continues. A second 403 shows an error state with a retry, not a hang (Task 8).
4. **Two plays racing the same enqueue.** The dedupe index raises 23505; the action returns the existing job instead of an error (Task 9).
5. **Malformed or foreign route params:**
   - `/read/<not-a-uuid>/1`, `/read/<id>/0`, `/read/<id>/abc`, `/read/<id>/99999`.
   - Another user's novel id (RLS returns nothing).
   - All of these return the 404 page, never a 500 (Task 7).

Rate limiter semantics (the part the tests pin):

```sql
-- inside api_rate_limit_hit, security definer, set search_path = ''
uid := auth.uid();                      -- null -> raise 42501
case p_bucket
  when 'audio_urls' then lim := 60; win := 60;
  when 'vitals'     then lim := 30; win := 60;
  else raise exception 'unknown rate-limit bucket %', p_bucket using errcode = '22023';
end case;
ws := to_timestamp(floor(extract(epoch from now()) / win) * win);
delete from public.api_rate_limits where user_id = uid and bucket = p_bucket and window_start < ws;
insert ... values (uid, p_bucket, ws, 1)
  on conflict (user_id, bucket, window_start) do update set hits = public.api_rate_limits.hits + 1
  returning hits into n;
return n <= lim;
```

`record_web_vitals` calls `public.api_rate_limit_hit('vitals')` once per call (not once per sample). It ignores array elements that fail the column checks: it filters with the same predicates instead of raising, so one bad sample does not drop the batch. Non-array input inserts nothing.
